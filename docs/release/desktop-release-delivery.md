# 0.0.1 安装与启动器实施清单

本页记录首版候选包的构建与验收。学生和教师可按[安装与使用说明](../guides/installation.zh-CN.md)选择平台和安装范围；[桌面发布规划](desktop-release.md)说明启动器行为和兼容性目标。

## 提交顺序与分工

| 批次 | 工作与依赖 | 交接给下一批的实物 |
|---|---|---|
| 1 · Windows 离线样包 | 打包维护先用现有 CLI 和浏览器入口制作应用目录。通过包内的实验发现机制加载两课。 | 一份可复制到另一目录运行的样包、构建命令，以及从样包保存且可重开的 α、β 文件各一份。后续平台复用这两份输入。 |
| 2 · 服务与 CLI | 框架维护基于现有服务划出启动、就绪、取消和停止的边界。CLI 接入明确的启动模式，沿用课程目录参数。此项可与批次 1 并行。 | 一个无桌面会话也能运行的服务入口。演示终端取 URL、浏览器读目录、Ctrl+C 后同一端口可再次绑定；GUI 维护据此接入。 |
| 3 · 启动器与设置 | GUI 维护先用延迟就绪和失败结果检查窗口，再接批次 2 的真实服务。打包维护将桌面入口加入样包。 | 从系统图标冷启动的实机录屏或截图序列，以及端口冲突、重试和自动打开次数的操作记录。 |
| 4 · 实验中关闭 | 框架与 GUI 维护先用“3 秒缓存、5 秒关窗”核对会话接口，然后接原生文件选择。CLI 维护核对导出文件可读。依赖批次 2、3。 | 三种关闭选择、写盘失败和两页交错的结果，附实际重开的文件及读数。批次 4 通过后固定本轮打包输入。 |
| 5 · 三端安装与交付 | Windows、macOS、Linux 可并行包装同一提交。教材维护依据实际安装入口补学生启动说明；各平台维护者核实步骤。 | 每个平台的安装附件、校验和、环境与通过的场景。主导复核一份干净环境记录及文件往返后，汇总发布说明。 |

## 启动接口与设置

**窗口先出现。** 从轻量桌面入口创建窗口，显示“正在启动…”，将课程发现、存储初始化和 HTTP 服务启动安排在首屏绘制之后。窗口线程只处理控件与系统对话框，后台将“就绪及实际地址”或“失败原因”交回窗口线程。就绪须以本次服务成功绑定端口并读回自身 `/api/catalog` 为准；其他服务对相同端口的响应不能证明新实例已启动。就绪检查不创建实验，也不用定时读取整谱。可复用[本机服务及入口测试](../../tests/test_web_entry.py)。

**实例归属。** 同一用户在课程目录、拟用端口和工作库存储配置相同时，普通重复使用桌面图标或 `serve --gui` 唤回已有桌面实例，包括它仍在启动的时候，不再创建服务或自动打开浏览器。明确另开、启动配置不同或只有终端服务在运行时，提供旧／新工作台选择；成功打开旧服务的实际地址后结束本次新启动，旧实验保留，启动新工作台则保留旧实例并使用独立服务及其地址。旧 Nuclemu 占用拟用端口时，并列的新服务使用可用端口；未知程序占用固定端口时明确报错。独立运行的 `serve --no-gui` 由其终端管理，保持非交互，不弹选择或静默复用；桌面窗口只能关闭自己拥有的服务。仅凭端口可连接或目录可读取不足以识别已有实例。三端共用此项行为验收。

显式另开入口为 `serve --gui --new-instance`，已有工作台时仍先显示“打开已有工作台”“启动并列服务”，不是直接绕过选择。多个旧服务按已验证的实际地址和课程目录挑选；复用失败保留选择与地址。不同配置的旧工作台尚在启动且没有实际地址时，提示稍后重试；同配置仍直接唤回。该参数仅用于 `serve --gui`，与 `--no-gui` 同用须报用法错误；原有 `gui` 命令继续由终端管理，不弹图形选择。

| 入口 | 配置与输出验收 |
|---|---|
| 桌面入口、`serve --gui` | 读取同一用户的启动器设置。实际端口由已绑定的服务器返回。开启自动打开时，每次新实例首次就绪只调用默认浏览器一次；手动按钮可重复使用。 |
| `serve --no-gui` | 建议沿用服务的自动端口默认值，就绪后向标准输出打印可直接复制的回环 URL，启动失败写标准错误并返回非零。无显示设备也能运行，桌面自动打开偏好不介入。 |
| CLI 兼容 | `serve` 的两种模式须选其一，参数错误可在创建服务前发现。两种模式均沿用现有 `--path` 的目录发现规则。用 `nuclemu gui` 核对原有自动打开行为，用 `list`、`run`、`files inspect` 核对原有非交互调用。 |

两项偏好保存在用户目录下的 `.nuclemu/launcher.json`，首次启动使用 `{"port": 0, "open_browser": false}`。设置窗口的“保存”写入两项，“取消”丢弃本次输入。就绪期间保存后，原地址和正在进行的实验继续可用。启动失败后可修改端口，点击“重试”使用新设置。配置文件无法写入时保留原值并就地显示错误。设置独立于实验交换文件。

## 关闭操作的接口交接

1. **取得关闭上下文。** 在服务锁内查看 `Application.lab`。无活动实验时进入停止流程，同时阻止排队的新开实验请求。有实验时复用当前会话 ID、冻结动作和确认编号；若浏览器已经发起确认，使用该次编号。关闭对话框显示期间保持窗口可回应。
2. **保存或取消。** 在锁外选择路径。取消关闭时，仍属于当前场次的确认才可恢复仿真。选择保存时，复核场次与确认编号，沿用该类型实验的整场导出器取得一致的数据，再在锁外用固定短前缀创建相邻临时文件并替换目标，不把完整目标文件名叠加到临时文件名上。若文件选择被取消或写入失败，保留实验与原文件，提供返回或重试。未缓存的当前读数按[测量工作流](../technical/measurement-workflow.md)处理。
3. **提交退出。** 写盘成功或学生明确放弃后，在锁内再次核对会话与确认编号，再结束该场次并停止服务。如果另一个页面已取消确认或换场，返回当前状态；原请求不得关闭新的实验。系统关窗和“关闭”按钮走同一流程；macOS 应用菜单、Dock 的退出及常规退出快捷键也进入这套确认，已有确认或文件选择器打开时不重复创建确认。启动中关闭先撤销本次就绪通知；等待后台收尾时仍能绘制窗口，延迟到达的结果不能再打开浏览器。

用例从[现有退出事务测试](../../tests/test_web_exit_transactions.py)扩展到真实启动器，并保留浏览器原有的退出流程。终端前台服务继续用 Ctrl+C 停止；CLI 帮助应说明学生可先在工作台下载数据，终端中断不会代为保存。

## 包内内容与安装路径

打包输入固定到源码提交、项目版本和前端锁文件。候选工序依次为构建生产前端、收集应用目录、在仓库外运行目录、制作平台安装载体。资源检查以 HTML 实际引用的 JS、CSS 及运行时读取的字体、图像和教材为准。内置课程由 [catalog.discover](../../nuclemu/catalog.py) 动态枚举，冻结后的包须通过正常发现路径列出 α、β；扩展模块仍从用户显式提供的可信目录加载。

| 平台交付 | 安装后的入口与特有检查 |
|---|---|
| Windows 主线 | 离线安装程序默认仅为当前用户安装，普通账户可用。另提供需要管理员权限的全机安装，供教师部署共享课机。两种范围各自注册开始菜单及卸载入口，升级沿用原范围，启动器偏好按用户保存。验收中文及带空格路径、从不同工作目录启动，以及升级后重开旧 `.nuclemu` 文件。 |
| macOS | DMG 内的 `.app` 拖入 Applications 后由 Finder 冷启动；同时提供可定位的 CLI 调用方式。Intel 与 Apple Silicon 分别记录实测架构和首次启动提示，从 Finder 保存到用户选定目录。 |
| Linux | `.deb` 注册应用菜单与终端命令，压缩包可从解压目录启动。图形桌面测菜单与默认浏览器，无显示会话测同一构建的 CLI。离线依赖说明列出目标系统须已有的系统库。 |

从安装目录外启动、断开外网、使用无开发工具的账户完成验证。安装与升级只更新程序资源；用户另存的实验文件由用户管理。组装产物时带上源码对应版本和所用第三方许可，校验和针对最终分发文件计算。Win7 SP1 有合适环境时复用同一套场景，单列结果，按[旧系统适配取舍](desktop-release.md#win7-sp1-的收益代价与取舍)决定是否继续。

## 验收记录

### Windows x64 目录样包，批次 1、2

构建环境为 Windows 11 x64 build 26300。断开外网的 Windows Sandbox build 26100 中没有 Python 或 Node 命令。将应用目录复制到沙箱本地后，以种子 187 分别采集 3 s，取得下列可重开的实验文件。

| 文件 | 已保存的测量 | 重开检查 |
|---|---|---|
| `AEL.nuclemu` | α 谱共 221 次，1,024 道，刻度为 0 道对应 0 MeV、1,000 道对应 6 MeV | 逐道计数和两点刻度随文件恢复。 |
| `BABS.nuclemu` | β 双窗分别设为 1 s 和 5 s。A 的三个完整窗合计 34,725 次，B 的部分窗曝光 3 s、计 34,778 次。 | 两窗计数、曝光和完整窗标志随整机记录恢复。 |

在沙箱和宿主分别使用 Edge 157.0.4341.46 打开文件，显示对应仪器，从实验记录下载整场文件；下载文件中的测量记录与原文件一致。宿主终端另验 Ctrl+C 后立即重绑端口，原生窗口另验启动中取消及活动实验关窗保护。Win10、Win7 SP1、双实体课机交换和系统安装程序均待验。

启动器在同一台 Windows 11 主机的两块显示器上使用目录包复验。窗口报告每显示器 DPI 感知 V2；从 200%（192 DPI）移到 150%（144 DPI）再移回，测得就绪窗口客户区依次为 1,000 × 484、754 × 369、1,000 × 484 像素。地址与操作在两个缩放比例下均完整可见。另在 Windows 11 沙箱查看整个窗口，确认顶部右侧三个系统按钮、正文软件名 Nuclemu 及就绪状态。实际点击最小化、最大化／还原、拖动、双击顶部均可操作；实验中点击关闭或按 Alt+F4 后保持同一场次，退出实验后可关闭窗口。

### Windows x64 启动器与设置，批次 3

目录包内的 `Nuclemu-Desktop.exe` 使用 Windows 图形子系统，`nuclemu.exe` 使用控制台子系统。两个入口共用一个运行时目录。断网 Windows 11 沙箱中从桌面程序进入 β 实验，在设置中选定固定端口、开启自动打开浏览器后保存，原地址仍返回同一场实验。将启动器最小化，再运行 `nuclemu.exe serve --gui`，同一窗口恢复，原场次仍可读取。

退出后让另一进程占用已保存的端口。启动器报告冲突，在原窗口设置另一个端口并重试后，两门课均可读取，占用旧端口的进程仍可连接。真实 Tk 测试还核对了浏览器调用次数：通过就绪检查后自动打开一次，唤回窗口不会再调用，手动按钮可以反复使用。

设置窗在 Windows 上保留右上角的系统关闭按钮，顶部空白处可拖动。端口使用「自动 / 固定」选择，浏览器偏好使用带文字状态的开关。在沙箱开启该偏好后，端口重试成功时，Edge 实际增加一个工作台标签页；再次运行桌面入口后标签总数相同。保存和取消均可用键盘操作。

同一台 Windows 11 主机上，将设置窗从 200% 的显示器移到 150% 的显示器再移回，实测客户区依次为 960 × 679、724 × 523、960 × 679 像素。固定端口输入框、浏览器开关及底部按钮在两个比例下都位于客户区内。

### 实验中关闭，批次 4

系统关闭按钮和启动器内的「关闭」共用同一个确认窗口。取消关闭会恢复原先正在采集的仪器；在系统文件选择窗口取消则返回关闭确认，可重选位置。保存时沿用实验记录中的测量和刻度，保留当前设置以及轮次信息。

在断网的 Windows 11 沙箱中关闭 β 的最后一个 Edge 实验页，再从目录包的启动器取消关闭，同一实验继续采集。再次关闭，用系统文件窗口选定路径，β 文件写入后启动器退出。用同一目录包另存 α，再在宿主机的新工作台中用 Edge 157.0.4341.46 打开这两个文件，进入相应仪器，从实验记录下载；两份文件中保存的各项记录与输入逐项一致。另从浏览器结束旧场、打开新场，确认旧窗口无法放弃新实验，再从新确认窗口放弃并退出成功。

用同一种子在 3 s 缓存读数，继续到 5 s 后从启动器服务保存。在新服务和 CLI 中重开，α 的 1,024 道合计 221 次，两点刻度保持一致；β 的 A 窗有三个完整窗，分别为 11,603、11,566、11,556 次，B 窗有一个 3 s 部分窗、34,778 次。两窗的缓存曝光均为 3 s。

另在本机模拟写入和替换文件失败，核对原文件字节及缓存，重选路径后可保存。写入过程中从浏览器取消退出或换场，原请求在替换文件前失效。只读历史实验连续另存后重开，原始记录标识、刻度及只读状态均保留。可分别运行[关闭事务测试](../../tests/test_web_service_close.py)和[文件往返测试](../../tests/test_desktop_close_exchange.py)复查。

### 三端安装包，批次 5

升级验收使用首版发布前的两个安装候选，检查程序文件替换、用户偏好和实验数据保留。可用[固定实验文件](../../packaging/samples/README.md)复查跨平台读数。

**Windows。** 在断网 Windows 11 x64 沙箱 build 26100 用普通账户验证按用户安装，用管理员账户验证全机安装。将旧测试候选升级到 0.0.1，安装范围和中文空格路径得到保留，淘汰的程序文件移除。通过开始菜单启动、复用已有窗口并关闭后，端口可再次绑定；卸载和重装后能读回原有偏好和实验文件。另在 Windows Server 2025 原生运行器独立构建并通过全机安装、升级、卸载和重装。[全机安装与验收输出](https://github.com/msjs2333/Nuclemu/actions/runs/43628969111)

当前安装器按固定 CPython 3.12.13 的上游范围设 `MinVersion=6.3`（Windows 8.1）。这项门槛与上述已测环境分开：未有 Windows 7、8 或 8.1 测试机，本轮不声称已实测旧系统拦截或 8.1 桌面／CLI 启动。取得旧机后分别核对：7 SP1 和 8 在复制程序文件前收到系统版本提示；8.1 完成桌面、CLI、采集和文件往返。Win7 SP1 仅为未来独立兼容构建目标。

**Linux。** 在断网 Debian 12 amd64 容器安装 `0.0.1-0`，用 `dpkg` 升级到 `0.0.1-1`，通过桌面菜单启动，卸载后检查菜单、程序和用户文件。普通用户的偏好和实验文件逐字节保留。便携包解压到含中文和空格的路径后运行，再移动目录重开实验；安装版和便携版重新导出的 α、β 文件均在 Windows 上读回。另在仅有声明的系统库、无 Python、Node、显示设备和外网的环境中实测 CLI、采集和本机服务。[构建、安装与验收输出](https://github.com/msjs2333/Nuclemu/actions/runs/43627703318)

另在本机断网容器的虚拟 X11 桌面安装同一份 Debian 包，设置 Firefox ESR 153.7.0 为默认浏览器，启用 Nuclemu 的自动打开偏好。从应用菜单启动后实际出现工作台浏览器窗口，载入两份基准档可见对应装置。该项使用 Xvfb 和 Openbox；容器测试进程因用户命名空间受限，关闭了 Firefox 内容沙箱。

**macOS。** 在 Intel macOS 15.7.9 和 Apple Silicon macOS 15.8.2 上分别构建 DMG。只读挂载后把应用复制到带中文和空格的 Applications 测试目录，卸载镜像再启动包内 CLI。包修订 1 替换为 2 后，旧资源已移除，设置和实验可重开；移除应用后，设置、工作台数据和实验文件保留。两个架构分别检查了 53 个原生二进制文件的依赖，并用 Windows 目录包读回了两个架构生成的谱、刻度和双窗读数。候选包使用 ad-hoc 签名。实体桌面的 Finder 首次启动、Gatekeeper、原生保存窗口和断网冷启动仍待验。[双架构构建与验收](https://github.com/msjs2333/Nuclemu/actions/runs/43626636558)

### 各平台安装包的复验场景

| 场景 | 可复现步骤和通过条件 |
|---|---|
| 启动慢或失败 | 延迟课程加载，先观察可移动的启动窗口，再关窗；后台结束后无新标签或监听端口。另用无关程序占用指定端口，修改并重试，显示的链接须指向新端口，无关程序仍在运行。 |
| 启动偏好与多次点击 | 从默认关闭开始，保存开启、退出并重开。新实例就绪时打开一次；同配置普通再次点图标只唤回同一窗口。关闭浏览器页再手动进入，仍能查看同一场实验。 |
| 旧／新工作台选择 | 分别覆盖无旧服务、其他端口已有服务、拟用端口由旧 Nuclemu 占用、未知程序占用固定端口。明确另开或课程不同时分别选旧／新，核对实际地址和各自课程；并列采集两场后关闭其中一场，另一场读数与采集状态保持。终端前台模式只报告冲突，不弹选择。 |
| 实验保存与恢复 | β 设 A 窗 1 s、B 窗 5 s，采到 3 s 缓存整机，继续到 5 s。关掉所有浏览器页，在启动器保存并关闭。用另一份安装产物重开，A 有三个完整窗，B 有一个 3 s 部分窗；两窗原始计数分别与缓存时一致。α 使用保存了谱和刻度的样本，对照逐道计数与同一道换算的能量。 |
| 取消、失败及并发 | 采集中关窗再取消，采集恢复；模拟无法写入，原目标字节与缓存均保留。原生对话框打开期间，从浏览器取消确认，按正常流程退出旧场并进入另一课；再确认旧对话框，新场次继续可用。macOS 另从应用菜单、Dock 和常规快捷键退出，核取消续采、保存重开及文件选择器打开时再次退出。 |
| 已有长文件名目标 | 覆盖文件系统已接受的长文件名，重开核对测量记录，并检查相邻临时文件没有残留；写入失败时旧文件完整，仍可重选路径。 |
| 安装、升级、卸载 | 各平台实际安装，核对两种入口、资料和仪器图片；用候选包覆盖安装，核对两个用户偏好和既有实验文件；卸载后端口释放，实验文件仍可复制。 |
