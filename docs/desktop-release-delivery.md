# 0.0.1 安装与启动器实施清单

本页供开发和验收使用。[桌面发布规划](desktop-release.md)定义学生看到的行为。批次 1、2 已提供 Windows x64 离线目录样包、服务生命周期和两种 CLI 入口。[样包构建与验证](../packaging/windows/README.md)说明如何构建、打开工作台和生成跨包对照文件。批次 3 至 5 继续在本分支推进。

## 提交顺序与分工

| 批次 | 工作与依赖 | 交接给下一批的实物 |
|---|---|---|
| 1 · Windows 离线样包 | 打包维护先用现有 CLI 和浏览器入口制作应用目录。通过包内的实验发现机制加载两课。 | 一份可复制到另一目录运行的样包、构建命令，以及从样包保存且可重开的 α、β 文件各一份。后续平台复用这两份输入。 |
| 2 · 服务与 CLI | 框架维护基于现有服务划出启动、就绪、取消和停止的边界。CLI 接入明确的启动模式，沿用课程目录参数。此项可与批次 1 并行。 | 一个无桌面会话也能运行的服务入口。演示终端取 URL、浏览器读目录、Ctrl+C 后同一端口可再次绑定；GUI 维护据此接入。 |
| 3 · 启动器与设置 | GUI 维护先用延迟就绪和失败结果检查窗口，再接批次 2 的真实服务。打包维护将桌面入口加入样包。 | 从系统图标冷启动的实机录屏或截图序列，以及端口冲突、重试和自动打开次数的操作记录。 |
| 4 · 实验中关闭 | 框架与 GUI 维护先用“3 秒缓存、5 秒关窗”核对会话接口，然后接原生文件选择。CLI 维护核对导出文件可读。依赖批次 2、3。 | 三种关闭选择、写盘失败和两页交错的结果，附实际重开的文件及读数。批次 4 通过后固定本轮打包输入。 |
| 5 · 三端安装与交付 | Windows、macOS、Linux 可并行包装同一提交。教材维护依据实际安装入口补学生启动说明；各平台维护者核实步骤。 | 每个平台的安装附件、校验和、环境与通过的场景。主导复核一份干净环境记录及文件往返后，汇总发布说明。 |

## 启动接口与设置

**窗口先出现。** 从轻量桌面入口创建窗口，显示“正在启动…”，将课程发现、存储初始化和 HTTP 服务启动安排在首屏绘制之后。窗口线程只处理控件与系统对话框，后台将“就绪及实际地址”或“失败原因”交回窗口线程。通过本次监听地址成功读取一次 `/api/catalog` 即可标记就绪；就绪检查不创建实验，也不用定时读取整谱。可复用[本机服务及入口测试](../tests/test_web_entry.py)。

**实例归属。** 同一用户再次使用桌面图标或 `serve --gui` 时唤回已有桌面实例，包括它仍在启动的时候。唤回不再创建服务或自动打开浏览器。独立运行的 `serve --no-gui` 由其终端管理；端口冲突时报告地址，桌面窗口只能关闭自己拥有的服务。仅凭端口可连接不足以识别已有桌面实例。三端可分别实现唤回机制，共用此项验收。

| 入口 | 配置与输出验收 |
|---|---|
| 桌面入口、`serve --gui` | 读取同一用户的启动器设置。实际端口由已绑定的服务器返回。开启自动打开时，每次新实例首次就绪只调用默认浏览器一次；手动按钮可重复使用。 |
| `serve --no-gui` | 建议沿用服务的自动端口默认值，就绪后向标准输出打印可直接复制的回环 URL，启动失败写标准错误并返回非零。无显示设备也能运行，桌面自动打开偏好不介入。 |
| CLI 兼容 | `serve` 的两种模式须选其一，参数错误可在创建服务前发现。两种模式均沿用现有 `--path` 的目录发现规则。用 `nuclemu gui` 核对原有自动打开行为，用 `list`、`run`、`files inspect` 核对原有非交互调用。 |

建议把两项偏好保存在用户目录下的 `.nuclemu/launcher.json`，与已有 `.nuclemu/workbench` 的实验存储分开。首次启动使用 `{"port": 0, "open_browser": false}`。设置窗口的“保存”写两项，“取消”丢弃本次输入。就绪期间保存后，主窗口继续显示当前实际地址；启动失败后的“重试”读取新端口，相当于新一次启动尝试。配置文件无法写入时保留原值并就地显示错误。设置不进入实验交换文件。

## 关闭操作的接口交接

1. **取得关闭上下文。** 在服务锁内查看 `Application.lab`。无活动实验时进入停止流程，同时阻止排队的新开实验请求。有实验时复用当前会话 ID、冻结动作和确认编号；若浏览器已经发起确认，使用该次编号。关闭对话框显示期间保持窗口可回应。
2. **保存或取消。** 在锁外选择路径。取消关闭时，仍属于当前场次的确认才可恢复仿真。选择保存时，复核场次与确认编号，沿用该类型实验的整场导出器取得一致的数据，再在锁外写相邻临时文件并替换目标。若文件选择被取消或写入失败，保留实验与原文件，提供返回或重试。未缓存的当前读数按[测量工作流](measurement-workflow.md)处理。
3. **提交退出。** 写盘成功或学生明确放弃后，在锁内再次核对会话与确认编号，再结束该场次并停止服务。如果另一个页面已取消确认或换场，返回当前状态；原请求不得关闭新的实验。系统关窗和“关闭”按钮走同一流程。启动中关闭先撤销本次就绪通知；等待后台收尾时仍能绘制窗口，延迟到达的结果不能再打开浏览器。

用例从[现有退出事务测试](../tests/test_web_exit_transactions.py)扩展到真实启动器，并保留浏览器原有的退出流程。终端前台服务继续用 Ctrl+C 停止；CLI 帮助应说明学生可先在工作台下载数据，终端中断不会代为保存。

## 包内内容与安装路径

打包输入固定到源码提交、项目版本和前端锁文件。候选工序依次为构建生产前端、收集应用目录、在仓库外运行目录、制作平台安装载体。资源检查以 HTML 实际引用的 JS、CSS 及运行时读取的字体、图像和教材为准。内置课程由 [catalog.discover](../nuclemu/catalog.py) 动态枚举，冻结后的包须通过正常发现路径列出 α、β；扩展模块仍从用户显式提供的可信目录加载。

| 平台交付 | 安装后的入口与特有检查 |
|---|---|
| Windows 主线 | 离线安装程序默认仅为当前用户安装，普通账户可用。另提供需要管理员权限的全机安装，供教师部署共享课机。两种范围各自注册开始菜单及卸载入口，升级沿用原范围，启动器偏好按用户保存。验收中文及带空格路径、从不同工作目录启动，以及升级后重开旧 `.nuclemu` 文件。 |
| macOS | DMG 内的 `.app` 拖入 Applications 后由 Finder 冷启动；同时提供可定位的 CLI 调用方式。Intel 与 Apple Silicon 分别记录实测架构和首次启动提示，从 Finder 保存到用户选定目录。 |
| Linux | `.deb` 注册应用菜单与终端命令，压缩包可从解压目录启动。图形桌面测菜单与默认浏览器，无显示会话测同一构建的 CLI。离线依赖说明列出目标系统须已有的系统库。 |

从安装目录外启动、断开外网、使用无开发工具的账户完成验证。安装与升级只更新程序资源；用户另存的实验文件由用户管理。组装产物时带上源码对应版本和所用第三方许可，校验和针对最终分发文件计算。Win7 SP1 有合适环境时复用同一套场景，单列结果，按[旧系统适配取舍](desktop-release.md#win7-sp1-的收益代价与取舍)决定是否继续。

## 验收记录

### Windows x64 目录样包，批次 1、2

构建环境为 Windows 11 x64 build 26300。断开外网的 Windows Sandbox build 26100 中没有 Python 或 Node 命令。将应用目录复制到沙箱本地后，以种子 187 分别采集 3 s，取得下列可重开的实验文件。

| 文件 | 已保存的测量 | 重开检查 |
|---|---|---|
| `AEL.nuclemu` | α 谱共 221 次，1,024 道，刻度为 0 道对应 0 MeV、1,000 道对应 6 MeV | 逐道计数和两点刻度随文件恢复。 |
| `BABS.nuclemu` | β 双窗分别设为 1 s 和 5 s。A 的三个完整窗合计 34,725 次，B 的部分窗曝光 3 s、计 34,778 次。 | 两窗计数、曝光和完整窗标志随整机记录恢复。 |

在沙箱和宿主分别使用 Edge 157.0.4341.46 打开文件，显示对应仪器，从实验记录下载整场文件；下载文件中的测量记录与原文件一致。宿主终端另验 Ctrl+C 后立即重绑端口，原生窗口另验启动中取消及活动实验关窗保护。Win10、Win7 SP1、双实体课机交换和系统安装程序均待验。

启动器在同一台 Windows 11 主机的两块显示器上使用目录包复验。窗口报告每显示器 DPI 感知 V2；从 200%（192 DPI）移到 150%（144 DPI）再移回，测得就绪窗口客户区依次为 1,000 × 484、754 × 369、1,000 × 484 像素。地址与操作在两个缩放比例下均完整可见。另在 Windows 11 沙箱查看整个窗口，确认顶部右侧三个系统按钮、正文软件名 Nuclemu 及就绪状态。实际点击最小化、最大化／还原、拖动、双击顶部均可操作；实验中点击关闭或按 Alt+F4 后保持同一场次，退出实验后可关闭窗口。

### 后续批次的验收场景

| 场景 | 可复现步骤和通过条件 |
|---|---|
| 启动慢或失败 | 延迟课程加载，先观察可移动的启动窗口，再关窗；后台结束后无新标签或监听端口。另用无关程序占用指定端口，修改并重试，显示的链接须指向新端口，无关程序仍在运行。 |
| 启动偏好与多次点击 | 从默认关闭开始，保存开启、退出并重开。新实例就绪时打开一次；再次点图标只唤回同一窗口。关闭浏览器页再手动进入，仍能查看同一场实验。 |
| 实验保存与恢复 | β 设 A 窗 1 s、B 窗 5 s，采到 3 s 缓存整机，继续到 5 s。关掉所有浏览器页，在启动器保存并关闭。用另一份安装产物重开，A 有三个完整窗，B 有一个 3 s 部分窗；两窗原始计数分别与缓存时一致。α 使用保存了谱和刻度的样本，对照逐道计数与同一道换算的能量。 |
| 取消、失败及并发 | 采集中关窗再取消，采集恢复；模拟无法写入，原目标字节与缓存均保留。原生对话框打开期间，从浏览器取消确认，按正常流程退出旧场并进入另一课；再确认旧对话框，新场次继续可用。 |
| 安装、升级、卸载 | 各平台实际安装，核对两种入口、资料和仪器图片；用候选包覆盖安装，核对两个用户偏好和既有实验文件；卸载后端口释放，实验文件仍可复制。 |

每项实测登记“提交与附件名、系统版本及架构、默认浏览器版本、操作、实际读数或错误、结论”。自动化测试注明运行环境，实体机、虚拟机和本机多进程分别标注。双实体课机交换沿用已有待验项。缺少运行环境的组合保留“待验”，发布说明据此列出已验证范围。
