# 0.0.1 桌面安装与启动器规划

学生从系统应用菜单启动 Nuclemu，在默认浏览器中完成实验。桌面窗口管理本机服务，浏览器继续承载实验目录、仪器和记录。首版交付 Windows、macOS 和 Linux 桌面安装包。旧 Windows 的期望支持下限是 Windows 7 SP1，验证结果独立登记，三端主线通过验收即可发布。下列组合是计划中的验证环境，最低实测版本在取得安装包后填写。

## 启动器

| 位置 | 控件与行为 |
|---|---|
| 窗口标题 | Nuclemu。主区域显示服务状态，例如“已就绪”；启动失败时在原位显示原因。 |
| 地址行 | 显示本次实际监听的完整本机链接，可点击、可选中复制。打开默认浏览器失败时仍可将地址粘贴到其他浏览器。 |
| 主操作 | 蓝色主按钮“在浏览器中打开”。启动服务成功后启用；反复点击只打开同一实例的地址。桌面启动默认先显示窗口，命令行现有的自动打开浏览器行为保留。 |
| 次操作 | “设置”和“关闭”并列。系统关闭按钮、快捷键和应用菜单中的退出共用关闭流程。关闭浏览器标签页后仍可由启动器回到当前实验。 |

采用工作台现有的墨色正文、浅灰工具面、蓝色主操作（`#2956a1`）和键盘焦点。地址与端口便于选取，中文字体沿用工作台的系统回退顺序。只在错误或可能丢弃数据时使用警示色。以桌面系统缩放 100%、150% 和键盘操作验收，核对长地址、中文和系统大字体不截断。[现有工作台样式](../nuclemu/static/style.css)

**设置只有端口。** 默认“自动”沿用现有端口 0 的系统分配行为，窗口显示实际端口。手动模式接受整数 1–65535，保存到当前用户的配置目录，下次启动生效。活动实验的链接与采集继续有效。固定端口被占用时保留窗口，显示端口和“修改端口”“重试”；绑定成功前不开浏览器。重复启动桌面入口应唤回已有窗口；遇到其他程序占用端口时不能将它识别为本应用。

## 关闭时保护实验

服务端持有的 `Application.lab` 决定是否在实验中。暂停采集、关闭所有浏览器标签或切到教材，都可能仍持有实验。启动器关闭的对象是自己创建的服务，浏览器内“退出实验”则回到实验目录。

| 点击关闭时 | 学生看到什么 | 服务如何处理 |
|---|---|---|
| 位于实验目录，无活动实验 | 直接退出 | 在服务锁内确认仍为空，再停止接受请求、释放端口。 |
| 已进入实验，包括暂停、采集中或由文件重开的实验 | “关闭前是否保存实验？”提供“保存并关闭”“放弃并关闭”“取消”。有未缓存读数时，沿用工作台的简短提示。 | 以当前会话和退出确认编号冻结待决定的实验。取消恢复原实验和原采集状态。放弃须作用于这次确认的场次。 |
| 选择保存 | 弹出系统保存文件对话框，采用既有实验短码和时间命名。 | 通过工作台相同的整场序列化路径取文件，写入成功再释放会话并退出。写入失败、磁盘满或取消选址，保留实验与缓存，允许重试或返回。 |

原生窗口可以直接获取写盘结果，即使所有浏览器页都已关闭也可保存。使用相邻临时文件完成写入后替换目标，失败保留旧文件。当前可携实验按既有规则保存已缓存读数、配置与轮次元数据；如已缓存 3 s、现场测到 5 s，保存并关闭后应能重开 3 s 的读数。学生要带走 5 s 的读数时，可取消退出，回仪器手动保存。历史只读档案沿用其已有保存路径。浏览器与启动器同时发起退出时复用同一确认，过时的响应不能关闭新场次。[测量工作流](measurement-workflow.md) · [整场文件](exchange.md)

## 实现边界

沿用 [本机 HTTP 服务](../nuclemu/web.py) 的 `make_server()`、回环地址及 [会话管理](../nuclemu/web_session.py)。建议用标准库 Tk/ttk 做独立小窗口，主线程运行窗口事件循环，工作线程运行 HTTP 服务。共享同一个应用实例和锁；关闭检查只需要查询活动会话和保存状态，无须轮询完整谱图。文件选择期间释放应用锁，提交关闭前重新核对会话与确认编号。窗口线程调度服务退出，等待服务线程返回再销毁窗口。保留现有 `nuclemu gui` 和 CLI，发布包提供独立桌面入口。这样可以分别测试端口、关闭流程和窗口。

## 安装包与兼容性

候选方案采用按平台构建的应用目录，内含启动器、CLI、解释器、Tk、SQLite、实验模块及预构建的 Web 资源（包括教材、图像、字体和许可）。学生机使用已安装的浏览器，无须 Python、Node 或联网安装依赖。先验证目录版，再制作系统安装载体。PyInstaller 的目录模式作为候选，构建机、Python、打包器、工具链和系统库版本随首个成功样包记录。[PyInstaller 构建说明](https://pyinstaller.org/en/stable/usage.html)

| 平台 | 候选交付物与首轮验收环境 |
|---|---|
| Windows | 带开始菜单入口与卸载项的离线安装程序。主线覆盖 Win10、Win11 x64 代表环境。记录系统版本、运行库和浏览器；普通用户在中文路径中完成安装与启动。Win7 SP1 和 Win8.1 另列旧机验证结果，各架构分别标注。 |
| macOS | 含 `.app` 的 DMG。分别在 Intel 与 Apple Silicon 上由 Finder 启动并打开系统默认浏览器。在干净账户验证下载后的首次启动、系统提示和卸载，记录最低实测 macOS 版本及签名、公证状态。 |
| Linux | 首选带桌面菜单入口的离线 `.deb`，另以同一应用目录的压缩包供其他发行版验证。先测 Ubuntu LTS、Debian 桌面 x86_64，在选定的最低 glibc 基线上构建，记录发行版、桌面环境、图形库及浏览器版本。 |

### Win7 SP1 的收益、代价与取舍

旧系统适配能让保留 Win7 的课机继续使用本机算力，教师可在新旧课机间分发同一课程和实验文件。收益取决于实际课机的位数、系统补丁和已装浏览器。目前缺少这组清单与安装实测，优先保留一份可重复的试装流程。

[项目元数据](../pyproject.toml) 要求 Python ≥3.11，官方 Python 3.11 的 Windows 下限为 8.1；Win7 对应的 3.8 已结束维护。直接降低整个项目的解释器要求，会把模块加载（如 `Number = int | float`）、静态资源路径（`Path.is_relative_to`）和 [SQLite 文件读写](../nuclemu/exchange.py) 的兼容成本带到日常开发。维护专用旧包能隔离运行时，但每次发布都多一套解释器、Tk、SQLite、打包工具和浏览器组合要复验。回环服务可离线运行，旧组件的上游维护状态仍需写进旧包说明。[Python 的 Windows 支持](https://docs.python.org/3.11/using/windows.html) · [Python 版本生命周期](https://devguide.python.org/versions/) · [SQLite 接口](https://docs.python.org/3.11/library/sqlite3.html#sqlite3.Connection.serialize)

建议主线保留当前 Python 基线，优先把同一 Windows 安装包送到可用的较旧系统试装。有代表性 Win7 SP1 环境时，再用独立构建配置验证一条完整路径。先看启动器、服务和生产浏览器资源能否运行，再验证 α、β 的采集、保存及与现代包双向重开。若唯一差异在文件适配层，可评估用临时 SQLite 文件读写相同库结构。若需要长期维护定制解释器、分叉物理模型或改变存档语义，停止本轮适配，登记具体阻断和最近实测通过的组合。仅通过启动检查的组合标为“试装”，只有整条路径通过的 OS、位数及浏览器组合才列入实测兼容范围。

浏览器是另一项独立验收。Win7 可用 Edge 109 作旧引擎样机，它是微软为该系统提供的最后一个 Edge 大版本。用实际生产资源验证 Vue 页面、谱图、逐窗表格、对话框和文件下载；特别核对 `ResizeObserver`、`Array.at` 和动态视口高度。Vite 的转换目标只覆盖部分语法兼容性。若默认浏览器无法运行工作台，提供可读的兼容说明和可复制地址；启动器仍可设置端口和关闭服务。现代平台再分别用 Edge、Safari、Firefox 或 Chromium 覆盖系统默认浏览器交接。[Edge 生命周期](https://learn.microsoft.com/en-us/lifecycle/products/microsoft-edge) · [Vite 7 构建目标](https://v7.vite.dev/config/build-options)

## 本分支的交付顺序

| 次序 | 工作 | 完成证据 |
|---|---|---|
| 1 | 用现代 Windows 做第一份可离线运行的应用目录 | 在无 Python、Node 和源码目录的课机上，经默认浏览器进入内置两课，保存并重开 α 谱和 β 双窗。核对资源收集、刻度、逐窗读数和曝光；这份包也作为其他平台的文件对照样本。 |
| 2 | 接通桌面窗口、端口设置和退出事务 | 用真实浏览器验证打开同一场次、自动端口、固定端口冲突及下次生效。逐项执行上面的关闭表，含浏览器已关、另页仍在操作、取消和写盘失败，退出后同端口可重新启动。 |
| 3 | 生成三端安装载体 | 在干净环境离线安装、首次启动、升级覆盖、卸载。配置写入用户目录；升级保留端口，卸载保留学生另存的实验。安装后的 CLI、两课、教材、谱图及设备图均从包内资源加载。 |
| 4 | 整理首发附件与实测矩阵 | 按版本、OS 和架构命名产物，附校验和、对应源代码、第三方许可及简短安装说明。逐个平台登记安装包与浏览器实测结果，区分已通过、存在限制和待验。 |

第一份现代样包完成后，有旧机环境即可并行试装。三端安装包按各自主线场景验收；Win7 SP1 的试装失败或环境待验均可随版本说明单列。后续提交在本分支补实现与证据，最低实测版本、安装工具和已知限制随各平台产物登记。
